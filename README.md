# Admin Assist

Прототип информационного модуля интеллектуальной поддержки деятельности администратора информационной системы. Работает локально или как сайт на PythonAnywhere с сохранением данных в SQLite.

**Онлайн-демонстрация:** [Открыть Admin Assist](https://angeldust17.pythonanywhere.com/).

**Тема курсовой:** «Проектирование информационного модуля интеллектуальной системы деятельности администратора информационной системы».

Инструкции по размещению: [GitHub + PythonAnywhere](DEPLOYMENT.md).

## Запуск

Нужен Python 3.10 или новее. Дополнительные библиотеки и подключение к интернету не требуются.

1. Откройте `start.bat` двойным щелчком.
2. Приложение откроется в браузере: http://127.0.0.1:8765.
3. Не закрывайте окно запуска во время работы. Для остановки нажмите в нём `Ctrl+C`.

Из терминала в папке приложения: `python app.py`.
Другой порт: `python app.py --port 8766`.
Без автоматического открытия браузера: `python app.py --no-browser`.

## Что можно сделать

Интерфейс оформлен как инженерный журнал. Главная страница — список обращений с переключением между открытыми, решёнными и всеми записями. Выбранная проблема открывается на отдельной странице: следующий шаг и основная рекомендация видны сразу, а шаги инструкции, объяснение приоритета и история раскрываются по запросу. База знаний и статистика доступны через верхнюю навигацию.

- Просмотреть сводку и журнал инцидентов, найти обращения по тексту, статусу и приоритету.
- Создать обращение с указанием проблемы, сервиса, влияния и срочности.
- Проверить анализ до сохранения: категория, объяснение, приоритет, количество подходящих инструкций.
- Получить до трёх рекомендаций с шагами и основанием подбора.
- Взять обращение в работу, записать решение, закрыть или повторно открыть его.
- Просмотреть историю обработки и статистику.
- Найти и добавить инструкции в базу знаний. Новые инструкции участвуют в последующих анализах.
- Экспортировать все обращения, включая учебные, в CSV с разделителем `;` и кодировкой UTF-8 с BOM.

## Демонстрационные данные и хранение

При первом запуске создаются 7 помеченных учебных инцидентов и 6 инструкций. Это примеры для проверки интерфейса; они входят в статистику. Новые пользовательские обращения не помечаются как демонстрационные.

Данные сохраняются в `data/admin-assist.sqlite3` и остаются после перезапуска. Чтобы сделать копию базы, остановите приложение и скопируйте этот файл. Существующая база при запуске не перезаписывается.

Для отдельной базы без учебных инцидентов:

```text
python app.py --db data/my-project.sqlite3 --empty
```

Параметр `--empty` действует только при создании новой базы; инструкции будут добавлены. Он не удаляет существующие обращения.

## Интеллектуальная часть

В обращении доступен режим **«Разобраться в причине»**. Выберите сценарий, начните расследование и отмечайте фактически выполненные проверки. Само приложение не подключается к инфраструктуре и не выполняет команды.

- Сценарии: проблемы входа, недоступность приложения и подключение к БД.
- Следующая проверка зависит от ответов и оставшихся гипотез.
- Для каждой версии показаны поддерживающие или противоречащие наблюдения.
- Ответ «Не удалось проверить» сохраняет неопределённость; исключение остальных версий само по себе не подтверждает причину.
- Когда необходимые наблюдения совпали, показываются рекомендации для поддержанной версии. Другие версии могут существовать одновременно.
- Прогресс хранится в SQLite. Исправление прежнего ответа пересчитывает ветку и снимает последующие ответы, сохраняя их прежнее состояние в истории обращения.
- Можно начать заново или выбрать другой сценарий. Предыдущие наблюдения остаются в истории.
- В решённых обращениях расследование доступно для просмотра; после возврата в работу его можно продолжить.

Движок — версия 1 базы правил в `investigation.py`. Проценты уверенности не рассчитываются. Набор гипотез ограничен выбранным сценарием; если подтверждающих наблюдений нет, модуль сообщает о недостатке данных.

Это объяснимая система правил, а не обученная нейросеть:

1. Категория определяется по взвешенным признакам в названии и описании. Для неоднозначных и неизвестных формулировок показывается необходимость проверки.
2. Приоритет определяется матрицей «влияние × срочность» из девяти комбинаций. Для событий безопасности действует нижняя граница: высокий приоритет.
3. Инструкции ранжируются по совпадению категории и ключевых слов; отображается до трёх результатов. Балл ранжирования не является вероятностью или оценкой точности.
4. Анализ и рекомендации фиксируются при регистрации инцидента. Последующее изменение базы знаний не меняет историю старых обращений.

Администратор проверяет результат и выполняет необходимые действия самостоятельно. Качество классификации на реальных обращениях пока не оценивалось; словарь правил требует адаптации под выбранную ИС.

## Состав проекта

- `app.py` — HTTP-сервер и API на стандартной библиотеке Python.
- `wsgi.py` — адаптер для размещения на PythonAnywhere; использует те же обработчики API.
- `deploy/pythonanywhere_wsgi.py` — готовая конфигурация хостинга.
- `domain.py` — классификация, приоритеты, рекомендации и проверка данных.
- `investigation.py` — сценарии расследования, вывод по наблюдениям и сохранение ответов с контролем версии.
- `database.py` — SQLite, схема и учебные примеры.
- `web/` — интерфейс на HTML, CSS и JavaScript без внешних зависимостей.
- `tests/` — проверки правил и полного цикла обработки через API.

При локальном запуске приложение слушает только `127.0.0.1`. В варианте для PythonAnywhere оно работает через сервер хостинга по HTTPS. Публичный учебный стенд использует отдельную общую базу: посетители видят изменения друг друга, вход в приложение не требуется. Используйте вымышленные сведения. Разделение прав пользователей, интеграции с реальной ИС и автоматический сбор журналов пока не реализованы.

## Проверка

В папке приложения выполните:

```text
python -m unittest discover -s tests -v
```

Дополнительная проверка отображения данных, фильтров и переключения записей (при установленном Node.js):

```text
node tests/test_frontend.cjs
```

Тесты используют временные базы и не меняют пользовательские данные.

## Сценарий демонстрации

1. Создайте обращение «Корпоративный портал недоступен» с описанием «Все сотрудники получают ошибку 503 при открытии портала».
2. Выберите влияние «Вся организация» и срочность «Работа остановлена».
3. Проверьте анализ: ожидается категория «Ошибки приложения», критический приоритет и инструкция по диагностике сервиса.
4. Создайте инцидент, откройте рекомендации и возьмите его в работу.
5. Введите решение не короче 10 символов, например «Проверены журналы, восстановлен сервис, доступ подтверждён», и отметьте инцидент как решённый.
6. Проверьте историю и изменение показателей на странице обзора.
